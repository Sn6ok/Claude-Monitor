## 1. Bridge — юніт-тести

Власний каркас на сотню рядків замість GoogleTest: тягнути бібліотеку заради
трьох макросів суперечило б вимозі мінімуму залежностей.

```powershell
cd bridge
cmake --build build
.\build\bridge_tests.exe
```

| Набір | Тестів | Що перевіряє |
|---|---|---|
| `json` | 13 | розбір, зокрема ворожий вхід і глибока вкладеність |
| `writer` | 5 | формування кадрів, екранування, межові числа |
| `redact` | 16 | маскування секретів **і відсутність хибних спрацювань** |
| `transcript` | 19 | нормалізація подій із реального формату Claude Code |
| `state` | 17 | ізоляція задач, межі памʼяті, машина станів |
| `queue` | 11 | обмеженість черги, пріоритети витіснення |
| `crypto` | 20 | примітиви проти контрольних векторів RFC |
| `pairing` | 6 | коди підтвердження, нормалізація вводу |

### Що саме перевіряється в найважливіших місцях

**Ізоляція задач** — не декларація, а перевірена властивість:

```text
кожна подія несе sid                          every_emitted_event_has_session_id
стан однієї задачі не тече в іншу             waiting_affects_only_target_session
помилка позначає лише свою задачу             error_in_one_session_does_not_mark_others
зникнення задачі не віддає її дані іншій      vanished_session_becomes_gone_not_finished
невідомий sid відкидається, а не приписується unknown_session_ignored_safely
```

**Межі памʼяті** — 50 000 подій у чергу без мережі не вичерпують памʼять:

```text
memory_does_not_grow_without_bound
session_limit_is_enforced
finished_history_is_bounded
recent_events_buffer_is_bounded
```

**Криптографія** — проти контрольних векторів, а не «сама з собою»:

```text
SHA-256("abc")            ba7816bf8f01cfea…   збігається
HMAC-SHA256 RFC 4231 №1   b0344c61d8db3853…   збігається
HKDF-SHA256 RFC 5869 №1   3cb25f25faacd57a…   збігається
```

## 2. Relay

```powershell
cd relay
npm test
```

| Набір | Тестів | Що перевіряє |
|---|---|---|
| протокол | 25 | валідація кадрів, усі випадки з Частини 6 §26 |
| автентифікація | 7 | підпис, replay, невідповідність ролі, таймаут |
| авторизація | 3 | чужий пристрій не бачить чужих даних |
| відкликання | 2 | діє **негайно**, не з наступного підключення |
| стійкість | 2 | сміттєві та завеликі пакети не валять сервер |
| обмеження частоти | 1 | потік кадрів обривається |
| конфіденційність | 2 | вміст не потрапляє на диск, у реєстрі немає ключів |
| health | 2 | не розкриває даних, інші маршрути дають 404 |

Особливо показові два тести:

- **`чужий монітор не отримує повідомлень навіть будучи автентифікованим`** —
  перевіряє саме те, чого вимагає Частина 3 §11: знання ідентифікатора
  нічого не дає.
- **`відкликання діє негайно на активну маршрутизацію`** — авторизація
  перевіряється на кожному кадрі, а не лише при вході.

## 4. Тести відмов

> Це найважливіший набір. Частина 6 §29 Master Prompt називає його критичним.

```powershell
.\scripts\failure-tests.ps1
```

Кожен сценарій навмисно ламає моніторинг і перевіряє, що **Claude Code
не постраждав**: порівнюється кількість процесів Claude Desktop, перелік
живих сесій і розмір транскриптів до та після.

| Сценарій | Результат |
|---|---|
| Аварійне завершення Bridge | Claude Code не зачеплено |
| Relay недоступний із самого початку | Claude Code не зачеплено |
| Relay падає посеред роботи | Claude Code не зачеплено |
| Relay повертається | Bridge автоматично відновлює звʼязок |
| Спроба запустити другий Bridge | другий екземпляр виходить сам |
| Потік сміттєвих пакетів | ані Bridge, ані Relay не впали |
| Хук без робочого Bridge | **18 мс** і вихід |
| Робота під наглядом | транскрипти не пошкоджено |

Останній рядок таблиці найважливіший для впливу на Claude Code: Claude Code
чекає завершення хука, тож 18 мс — це та затримка, яку монітор додає
до старту сесії. Один раз за сесію.

**Результат останнього запуску:** 8 з 8. Claude Desktop до тестів —
13 процесів і 3 сесії; після — так само 13 і 3.

## 5. Сумісність криптографії між платформами

Найризикованіше місце проєкту: три реалізації на трьох платформах мають
розуміти одна одну. Перевірено окремо, до написання решти коду.

| Перевірка | Результат |
|---|---|
| Node приймає публічну точку P-256 з CNG | так |
| Node перевіряє підпис CNG (IEEE P1363) | так |
| `device_id` збігається на обох сторонах | так |
| HKDF CNG == HKDF Node == RFC 5869 | так |
| Node дешифрує шифротекст AES-GCM з CNG | так |
| UTF-8 у корисному навантаженні зберігається | так |
| Формат nonce однаковий | так |
| Точки ECDH взаємно імпортуються | так |

## 6. Бенчмарк ресурсів

```powershell
.\scripts\benchmark.ps1 -SampleSeconds 60
```

Міряє три режими: без мережі, підключений, з приєднаним монітором.
Свіжі результати — [benchmark-results.md](benchmark-results.md).

Режим «без мережі» найважливіший: черга наповнюється, а віддати події
нікуди. Якщо памʼять там зростає — це витік.

## 7. Тривалий прогін

```powershell
.\scripts\longrun.ps1 -Minutes 60
```

Періодично знімає RAM, кількість дескрипторів і потоків. Зростання будь-чого
з них означає витік. Результати — [longrun-results.md](longrun-results.md).

Пороги: RAM +5 МБ, дескриптори +50, потоки +2. Вони підібрані так, щоб
не реагувати на звичайні коливання розподільника памʼяті, але помітити
систематичне зростання.

## 8. Ручні перевірки

Те, що неможливо автоматизувати без фізичного телефона.

### Життєвий цикл

- [ ] Після перезавантаження Windows Bridge **не працює**
- [ ] Після старту сесії Claude Code Bridge зʼявляється
- [ ] Після закриття Claude Desktop Bridge зникає
- [ ] Після повторного запуску Claude Desktop Bridge зʼявляється знову

### Наскрізна робота

- [ ] Встановлення APK
- [ ] Підключення за кодом
- [ ] Задачі видно на телефоні
- [ ] Події надходять у реальному часі
- [ ] Закриття застосунку не зупиняє Claude Code
- [ ] Повторне відкриття показує актуальний стан

### Мережа

- [ ] Wi-Fi → мобільний інтернет: перепідключення без дій користувача
- [ ] Режим польоту та назад: відновлення
- [ ] Тривалий екран блокування: стан актуальний після розблокування

### Безпека

- [ ] Невірний код відхиляється
- [ ] Код не працює вдруге
- [ ] Після відкликання телефон втрачає доступ негайно

## 9. Що знайшли тести

Перелік реальних дефектів, які не дійшли до релізу саме завдяки тестам.

| Дефект | Як знайдено | Наслідок, якби лишився |
|---|---|---|
| `field("t","status")` писав `true` | юніт-тест `writer` | зіпсовані кадри протоколу |
| `WINHTTP_OPTION_RECEIVE_TIMEOUT` не діє на WebSocket | наскрізна перевірка | знімок стану ніколи не доходив |
| Мережа блокувала спостереження | наскрізна перевірка | порушення Частини 5 §19 |
| Стара історія надходила як живі події | наскрізна перевірка | лавина подій при кожному підключенні |
| Читання памʼяті чужого процесу | самоперевірка за Master Prompt | порушення Частини 5 §11 |
| `pair_claim` вимагав `offer_id` | написання клієнта | pairing був би неможливий із застосунку |
| Код pairing не зʼявлявся при перенаправленні виводу | тест відмов | користувач не побачив би коду зі скрипта |
