# Якщо щось не працює

> Тут описано лише реальні причини й реальні перевірки. Функції, яких
> система не має, не видаються за тимчасові несправності
> (Частина 6 §41 Master Prompt).

---

## Bridge не запускається разом із Claude Desktop

```text
перевірте по черзі
        │
        ├─ 1. чи встановлено хуки?
        │     %USERPROFILE%\.claude\settings.json має містити розділ "hooks"
        │     згенерувати: claude-monitor-bridge.exe --install-hooks
        │
        ├─ 2. чи правильний шлях у хуку?
        │     він має вказувати на реальне розташування .exe
        │
        ├─ 3. чи почалася сесія Claude Code?
        │     хук SessionStart спрацьовує на початку сесії,
        │     а не при запуску Claude Desktop
        │
        └─ 4. що каже діагностика?
              claude-monitor-bridge.exe --status
```

Запустіть Bridge вручну й подивіться, що станеться:

```powershell
.\claude-monitor-bridge.exe --console --log-level debug
```

---

## `--status` не бачить Claude Desktop

Bridge шукає процес, шлях якого містить `\WindowsApps\Claude` або
`\AnthropicClaude\`, і який не є дочірнім процесом Chromium.

Перевірте, чи Claude Desktop справді працює:

```powershell
Get-Process claude -ErrorAction SilentlyContinue |
  Select-Object Id, Path
```

Якщо Claude Desktop встановлено нестандартно, Bridge його не впізнає.
Це не заважає моніторингу задач: сесії Claude Code виявляються окремо,
через реєстр. Втрачається лише автоматичне завершення Bridge разом
із Claude Desktop.

## Не видно активних задач

```powershell
.\claude-monitor-bridge.exe --status
```

Розділ «Активних задач Claude Code» показує те, що Bridge реально бачить.

Якщо там порожньо, а Claude Code працює — перевірте реєстр сесій:

```powershell
Get-ChildItem "$env:USERPROFILE\.claude\sessions" -Filter *.json
```

Порожній каталог означає, що ваша версія Claude Code не веде реєстру.
Тоді Bridge зможе відстежувати лише ту сесію, яка повідомила про себе
через хук.

## Телефон не підключається

### «Невірний код або час дії минув»

| Причина | Що зробити |
|---|---|
| минуло понад 3 хвилини | згенерувати новий: `--pair` |
| код уже використано | коди одноразові, потрібен новий |
| помилка при введенні | застосунок виправляє I↔1, O↔0, U↔V автоматично |
| Bridge не в мережі | перевірте, що `--pair` ще працює у вікні |

### «Немає звʼязку з сервером»

```powershell
# чи живий Relay взагалі
curl http://127.0.0.1:8787/health

# чи живий тунель
curl https://ваша-адреса/health
```

Обидві команди мають повернути `{"ok":true,…}`.

Перевірте адресу в застосунку: має бути `wss://…/ws` — саме `wss`
і саме зі шляхом `/ws`.

### «Забагато спроб»

Спрацював захист від перебору: 5 невдалих спроб — і 15 хвилин блокування.
Зачекайте або перезапустіть Relay (лічильники живуть у памʼяті).

## Застосунок показує «Немає звʼязку»

```text
        ┌─ Relay працює?          curl https://адреса/health
        │
        ├─ Bridge працює?         --status покаже «Робочий Bridge: працює»
        │
        ├─ Bridge бачить Relay?   у журналі має бути «автентифіковано на Relay»
        │                         %USERPROFILE%\.claude-monitor\bridge.log
        │
        └─ пристрій не відкликано?  node relay/src/index.js devices
```

Застосунок перепідключається сам, із паузами 1, 2, 4, 8, 16, 32, 60 секунд.
Натискати нічого не треба — але кнопка «Перепідключитися» в налаштуваннях
скидає цю паузу.

---

## «Ноутбук поза мережею»

Телефон підключився до Relay, а Bridge — ні.

```powershell
Get-Content "$env:USERPROFILE\.claude-monitor\bridge.log" -Tail 20 -Encoding UTF8
```

| Що в журналі | Причина |
|---|---|
| `код 12029` | Relay недосяжний за вказаною адресою |
| `перевірка сертифіката TLS не пройдена` | проблема з сертифікатом; **не вимикайте перевірку** |
| `адресу Relay не налаштовано` | виконайте `--set-relay` |
| `пристрій не спарений` | виконайте `--pair` |

## Стан задачі — «НЕВІДОМО»

Це не збій, а чесна відповідь: Bridge не має надійних даних про стан.

Найімовірніша причина — Claude Code оновився й змінив формат транскрипту.
Решта функцій при цьому працює: задачі видно, події надходять.

---

## Назва задачі виглядає дивно

Назва береться за таким порядком:

1. `custom-title` — назва, задана явно
2. автоматична назва Claude Code
3. текст **першого** запиту сесії
4. назва робочого каталогу

Застосунок показує джерело під назвою, якщо це варіант 3 або 4.
Щоб назва була осмисленою, задайте її явно в Claude Code.

---

## Bridge завершується одразу після запуску

Найімовірніше, він уже працює: одночасно допускається лише один екземпляр.

```powershell
Get-Process claude-monitor-bridge
```

У журналі буде рядок «Bridge уже працює, завершуюсь». Це нормальна
поведінка, а не помилка.

---

## Кракозябри в консолі

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

Bridge і Relay перемикають консоль на UTF-8 самі, але перенаправлений
вивід читайте з `-Encoding UTF8`:

```powershell
Get-Content "$env:USERPROFILE\.claude-monitor\bridge.log" -Encoding UTF8
```

## Як прибрати систему

```powershell
# 1. відкликати телефон
node relay\src\index.js devices
node relay\src\index.js revoke <id>

# 2. прибрати хуки з %USERPROFILE%\.claude\settings.json

# 3. зупинити Bridge
Get-Process claude-monitor-bridge | Stop-Process

# 4. видалити дані
Remove-Item "$env:USERPROFILE\.claude-monitor" -Recurse
```

У застосунку — «Відʼєднати цей телефон»: це знищить ключі в Keystore.

Каталог `~/.claude` чіпати не потрібно: він належить Claude Code,
і Bridge у ньому нічого не змінював.

---

## Чого система не робить

Це межі проєкту, а не несправності:

| | |
|---|---|
| не показує екран ноутбука | навмисно: це не віддалений робочий стіл |
| не дозволяє керувати Claude з телефона | версія 1 працює лише на перегляд |
| не працює у фоні на телефоні | зʼєднання живе, поки застосунок відкритий |
| не показує відсоток виконання | Claude Code не публікує такої метрики |
| не стартує разом із Windows | навмисно: запускається з сесією Claude Code |

---

## Зібрати дані для звіту про помилку

```powershell
.\claude-monitor-bridge.exe --status
Get-Content "$env:USERPROFILE\.claude-monitor\bridge.log" -Tail 50 -Encoding UTF8
```

Перед тим як кудись надсилати журнал, перегляньте його. Секретів там бути
не повинно — журнал містить лише короткі ідентифікатори й коди подій, —
але шляхи до ваших проєктів у ньому є.
