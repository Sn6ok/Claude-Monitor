# Android Monitor

> Застосунок показує стан і нічого більше. Він не може виконати команду,
> змінити файл чи натиснути щось на ноутбуці — це закладено в архітектуру,
> а не лише відсутнє в інтерфейсі.

---

## 1. Екрани

```text
   ПІДКЛЮЧЕННЯ                СПИСОК ЗАДАЧ              ДЕТАЛІ ЗАДАЧІ
   адреса + код        →      картки всіх сесій    →    події однієї задачі
                                     │
                                     ├──────────→       СПІЛЬНА СТРІЧКА
                                     │                  події всіх задач
                                     │
                                     └──────────→       НАЛАШТУВАННЯ
                                                        стан, безпека, доступ
```

### Список задач

Головний екран. Кожна сесія Claude Code — окрема картка:

```text
┌──────────────────────────────────────────┐
│ ● ПРАЦЮЄ                        bd9e74e7 │
│ Master prompt review                     │
│ Input Recoder · main                     │
│ ├─ створює src/core/event_queue.cpp      │
│ └─ 6:33:40                    12 с тому  │
└──────────────────────────────────────────┘
```

Порядок карток не випадковий: спершу задачі з помилкою, далі ті, що чекають
на вас, потім робочі. Те, що потребує уваги, завжди вгорі.

Угорі — агрегований підсумок: скільки активних, скільки працює, скільки
чекає, скільки помилок.

Над задачами — картки [вузлів](nodes.md), якщо вони є: розширення, які
власник комп'ютера сам поклав у свою папку.

```text
  ВУЗЛИ
┌──────────────────────────────────────────┐
│ ● Система                                │
│   Процесор                          32 % │
│   Вільна пам'ять           6.1 / 7.9 ГБ  │
└──────────────────────────────────────────┘
```

Застосунок не довіряє тому, що прийшло: вузол без `id` відкидається,
читається не більше 16 вузлів і 12 рядків у картці. Коли вузол не дав
даних, приходить код причини, а текст застосунок пише сам — мовою
інтерфейсу, а не чужим повідомленням.

### Деталі задачі

Стрічка подій **саме цієї** задачі, її поточна дія, час роботи, коли
востаннє щось змінювалося.

Якщо задача зникла, доки екран був відкритий, застосунок так і каже —
«задача більше не активна» — замість підстановки чужих даних.

### Спільна стрічка

Події всіх задач в одному потоці, кожна позначена своєю задачею:

```text
14:32:18  bd9e74e7  · створює event_queue.cpp
14:32:24  46ded809  ▸ ОЧІКУЄ
14:32:31  bf9f1ff9  · виконує npm test
14:32:42  bf9f1ff9  ✓ 42 tests passed
```

Порядок визначається глобальним номером події, а не часом: годинники
пристроїв можуть розходитися, а нумерація — ні.

## 2. Ізоляція задач

Вимога «дані однієї задачі не потрапляють у картку іншої» виконана
технічно, а не перевірками в інтерфейсі.

```kotlin
val tasks: Map<String, TaskSession>          // за ідентифікатором сесії
val taskEvents: Map<String, List<Event>>     // події теж за нею
```

**Поля «поточна задача» не існує.** Немає місця, куди можна було б
випадково записати чужий стан.

| Ситуація | Що відбувається |
|---|---|
| подія без `sid` | **відкидається** |
| подія з невідомим `sid` | **відкидається** |
| задача зникла | її дані зникають разом із нею |
| помилка в одній задачі | інші не змінюють стану |
| відкрита задача зникла | екран повертається до списку |

Перевірено 7 тестами в Bridge і 3 в застосунку.

## 3. Обмеження памʼяті

Жодна структура не росте необмежено (Частина 4 §21 Master Prompt).

| | Межа |
|---|---|
| Задач одночасно | 16 |
| Подій на задачу | 2000 і до 1,5 млн символів тексту; витісняється найдавніше |
| Подій у спільній стрічці | 2000 і до 1,5 млн символів тексту; знімок лише доповнює |
| Завершених в історії | 20 |
| Розмір кадру | 64 КБ |

## 4. Мережа

### Життєвий цикл зʼєднання

Застосунок тримає зʼєднання **лише поки він на екрані**:

```text
onResume  →  підключення, автентифікація, запит стану
onPause   →  зʼєднання закривається
```

Фонового сервісу немає навмисно. Тримати сокет заради екрана, на який
ніхто не дивиться, означало б витрачати батарею без користі: монітор
потрібен саме тоді, коли на нього дивляться.

### Перепідключення

```text
спроба:  1    2    3    4     5     6     7+
пауза:   1с   2с   4с   8с    16с   32с   60с (стеля)
джитер:  ±20%
```

Джитер обовʼязковий: без нього після падіння Relay усі клієнти повернулися б
синхронно й повалили б його знову.

Лічильник скидається після **успішної автентифікації**, а не після
встановлення зʼєднання. Інакше цикл «підключився — відмовили» перетворився б
на потік спроб.

### Зміна мережі

OkHttp сам виявляє розрив при переході Wi-Fi ↔ мобільний інтернет.
Далі спрацьовує звичайне перепідключення: автентифікація, запит стану,
продовження. Дій від користувача не потрібно.

### Виявлення пропусків

Кожна подія має номер. Якщо в послідовності зʼявився розрив, застосунок
запитує повний стан замість того, щоб добудовувати картину здогадками.

## 5. Безпека на телефоні

| | |
|---|---|
| Приватні ключі | Android Keystore, за наявності — апаратний модуль |
| Експорт ключів | неможливий |
| Резервне копіювання | вимкнено (`allowBackup=false`) |
| Перевірка сертифіката | системна, вимкнути неможливо |
| Дозволи | `INTERNET`, `ACCESS_NETWORK_STATE` |

Дозволів навмисно два. Немає доступу до камери, мікрофона, розташування,
контактів, сховища.

У сховищі застосунку немає й не буде: облікових даних Claude, ключів API,
вихідного коду, транскриптів, паролів.

### Що показано в налаштуваннях

```text
Транспорт              TLS
Шифрування подій       наскрізне (AES-256-GCM)
Ключі пристрою         Android Keystore
Сервер бачить вміст    ні
Режим застосунку       лише перегляд
```

Кожен рядок відповідає реальній архітектурі. Частина 6 §42 Master Prompt
забороняє писати «наскрізне шифрування», якщо його немає — тут воно є.

## 6. Чесність інтерфейсу

Застосунок ніколи не вигадує даних.

**Джерело назви показано явно.** Якщо назва виведена з тексту запиту або
з назви каталогу, під нею так і написано — «назва з тексту запиту».
Користувач бачить різницю між заданою назвою і здогадкою.

**Стан `НЕВІДОМО`** — повноцінний стан, а не збій. Якщо після оновлення
Claude Code формат транскрипту зміниться, застосунок покаже «не знаю»,
а не вигадає щось правдоподібне.

**Застарілі дані позначені.** Якщо оновлень не було понад 30 секунд,
зʼявляється позначка «дані застаріли». Це відрізняє спокій від обриву
звʼязку.

**Порожній стан пояснює причину.** «Немає звʼязку», «ноутбук поза мережею»
і «немає активних задач» — три різні повідомлення, а не одне загальне.

## 7. Технічні рішення

| Рішення | Причина |
|---|---|
| Kotlin + Compose | нативний Android; Compose дає компактний код без WebView |
| `org.json` замість бібліотеки серіалізації | входить в Android, не додає жодного байта до APK |
| Власний Base64url | логіка тестується на JVM; `android.util.Base64` там недоступний |
| OkHttp | єдина зовнішня залежність; коректно працює зі зміною мережі |
| Один таймер на екран | замість таймера в кожній картці: менше перемальовувань |
| Без Navigation-бібліотеки | пʼять екранів не варті окремої залежності |
| R8 + shrinkResources | APK 1.32 МБ замість 11.9 МБ |

---

## 8. Доступність

- Колір **ніколи не єдине джерело**: стан завжди дубльований текстом.
- Кольори станів розрізняються і за яскравістю — лишаються розпізнаваними
  при дальтонізмі.
- Моноширинний шрифт для шляхів і команд: їх треба читати точно.
- Підтримка світлої й темної теми.

## 9. Збірка

```powershell
cd android

# налагоджувальна
.\gradlew.bat assembleDebug

# тести
.\gradlew.bat testDebugUnitTest

# реліз (потрібне сховище ключів)
$env:CM_KEYSTORE = "C:\шлях\release.jks"
$env:CM_KEYSTORE_PASSWORD = "…"
$env:CM_KEY_PASSWORD = "…"
.\gradlew.bat assembleRelease
```

Без змінних середовища збирається непідписаний APK — це помітно одразу,
на відміну від мовчазного використання тестового ключа.

| | Розмір |
|---|---|
| Debug APK | 11.92 МБ |
| Release APK | **1.32 МБ** |

Найбільша частина релізу — `classes.dex` (2.1 МБ до стиснення), решта
здебільшого Compose.
