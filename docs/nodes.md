# Вузли (Nodes)

Вузол — розширення Claude Monitor: маленька програма на вашому комп'ютері,
яка щось вимірює і друкує це одним рядком JSON. Bridge запускає її за
розкладом, а застосунок показує результат окремою карткою над задачами.

Задумано як моди до гри: поклали каталог у папку — працює, прибрали — немає.
Ні реєстрації, ні перезбирання, ні правок у коді.

---

## 1. Де лежать вузли

```
%USERPROFILE%\.claude-monitor\nodes\
├── system-info\
│   ├── node.json
│   └── run.ps1
└── disk-space\
    ├── node.json
    └── run.ps1
```

Встановити вузол:

```powershell
.\scripts\install-node.ps1 .\nodes\system-info
.\scripts\install-node.ps1 -List
.\scripts\install-node.ps1 -Remove system-info
```

Скрипт лише копіює каталог, тому те саме можна зробити провідником.

Bridge перечитує папку **кожні 10 секунд**: новий вузол з'являється сам,
видалений зникає сам, перезапускати нічого не треба.

---

## 2. `node.json`

```json
{
  "id": "system-info",
  "name": "Система",
  "description": "Процесор, вільна пам'ять і час роботи",
  "version": "1.0.0",
  "run": "run.ps1",
  "intervalSec": 15,
  "timeoutSec": 10,
  "enabled": true
}
```

| Поле | Обов'язкове | Типове | Опис |
|---|---|---|---|
| `id` | ні | ім'я каталогу | лише `A–Z a–z 0–9 . _ -`, до 48 символів |
| `name` | ні | `id` | підпис картки в застосунку, до 48 символів |
| `description` | ні | — | для `-List`, у застосунок не йде |
| `version` | ні | — | ваша нумерація, до 24 символів |
| `run` | так* | — | що запускати; шлях — відносно каталогу вузла |
| `commands` | ні | — | правила: як підписувати команди в чаті (§4) |
| `intervalSec` | ні | `30` | як часто запускати; менше за `5` не буває |
| `timeoutSec` | ні | `10` | скільки чекати; більше за `30` не буває |
| `enabled` | ні | `true` | `false` — вузол лежить, але не запускається |

\* Вузол мусить мати або `run`, або `commands`: маніфест, який не робить
ні того, ні іншого, вузла не створює. Bridge пише про це в журнал і йде далі.
Вузол лише з `commands` нічого не запускає — він тільки підписує команди.

## 3. Що вузол друкує

Один об'єкт JSON у `stdout`, потім вихід із кодом `0`:

```json
{
  "status": "ok",
  "lines": [
    { "label": "Процесор", "value": "32 %" },
    { "label": "Вільна пам'ять", "value": "6.1 / 7.9 ГБ" }
  ],
  "text": "Необов'язковий текст під рядками"
}
```

| Поле | Опис |
|---|---|
| `status` | `ok` (сіро-синя крапка), `warn` (жовта), `error` (червона); невідоме значення читається як `ok` |
| `lines` | до **12** пар «підпис — значення»: підпис до 48 символів, значення до 160 |
| `text` | вільний текст до 512 символів |

Порожня картка (ні `lines`, ні `text`) вважається помилкою `bad_output` —
краще показати «даних немає», ніж порожню рамку.

**Кодування.** Bridge читає `stdout` як UTF-8. У PowerShell 5.1 додайте
першим рядком:

```powershell
[Console]::OutputEncoding = New-Object System.Text.UTF8Encoding $false
```

**Мова.** `run` вибирає спосіб запуску за розширенням:

| Розширення | Запускається як |
|---|---|
| `.ps1` | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File …` |
| `.js`, `.mjs` | `node …` |
| `.py` | `python …` |
| `.cmd`, `.bat` | `cmd.exe /c …` |
| інше (`.exe`) | напряму |

Якщо в `run` є пробіли, рядок вважається готовою командою і не змінюється:
`"run": "node tools\\collect.js --short"`.

## 4. Рядки в чаті: `commands`

Картка показує стан. Але вузол може ще й **підписувати команди**, які виконує
Claude Code, — тоді в чаті задачі поруч із дією з'являється зрозумілий рядок:

```text
  [10:24:31] › виконує команду
             python click.py 640 300 "Файл"
  [10:24:31] ⚙ Claude Click
             Натискаю: Файл
```

```json
"commands": [
  {
    "match": "click.py",
    "args": ["x", "y", "label"],
    "text": "Натискаю: {label}",
    "fallback": "Натискаю: точка {x}, {y}"
  }
]
```

| Поле | Обов'язкове | Опис |
|---|---|---|
| `match` | **так** | підрядок команди; регістр не важливий (шляхи Windows) |
| `text` | **так** | шаблон рядка; `{ім'я}` підставляє аргумент |
| `args` | ні | імена слів після `match`, за порядком |
| `fallback` | ні | запасний шаблон, коли якогось аргументу немає |

Як це працює:

1. Claude Code виконує команду, Bridge бачить її в транскрипті задачі.
2. Команда ділиться на слова з урахуванням лапок; слова після `match`
   стають значеннями `args` — `click.py 640 300 "Файл"` дає
   `x=640`, `y=300`, `label=Файл`.
3. Якщо всі потрібні значення є — у чат іде `text`, якщо ні — `fallback`,
   а якщо немає і його, рядка не буде взагалі.

Межі: до **8** правил на вузол, до **8** аргументів у правилі, рядок — до
**160** символів. На одну команду йде **один** рядок: спрацьовує перше
правило, яке підійшло, тож мод не може перетворити чат на власний потік.

Чому правило живе у вузлі, а впізнає команду Bridge: вузол не бачить ні
транскриптів, ні задач, ні тексту розмови — він лише каже, як назвати
команду. Рядок додається **тій задачі, яка цю команду виконала**, тому
приписувати його навмання не доводиться. У застосунку такий рядок помічено
знаком ⚙ і назвою вузла: видно, що це слова мода, а не Claude.

## 5. Коли даних немає

Застосунок ніколи не показує чуже повідомлення про помилку — Bridge надсилає
**код**, а текст пише застосунок своєю мовою:

| Код | Коли | Текст у застосунку |
|---|---|---|
| `start_failed` | програму не вдалося запустити | вузол не вдалося запустити |
| `timeout` | не вклався в `timeoutSec` | вузол не встиг відповісти |
| `exit_code` | вийшов із ненульовим кодом | вузол завершився з помилкою |
| `bad_output` | надрукував не той JSON або порожню картку | вузол надіслав не ті дані |
| `too_large` | надрукував понад 64 КБ | вузол надіслав забагато даних |

Завислий вузол знімається примусово; наступний запуск відбувається за
розкладом, як завжди.

---

## 6. Безпека

Вузол — **чужий код, який виконується з вашими правами**. Тому межі жорсткі:

* вузли беруться лише з вашої папки — Bridge нічого не завантажує з мережі
  й нічого не встановлює сам;
* кожен запуск обмежений часом (`timeoutSec`, максимум 30 с) і обсягом
  виводу (64 КБ); вузлів не більше 16;
* вузол запускається без вікна, у власному каталозі, окремим процесом і
  працює в окремому потоці Bridge: повільний вузол не гальмує ні читання
  транскриптів, ні мережу;
* вузол **не отримує** ні ключів, ні коду підключення, ні вмісту ваших
  сесій — він нічого не знає про Claude Code і не може нічого надіслати
  телефону повз Bridge;
* усе, що вузол надрукував, проходить те саме маскування секретів, що й
  звичайні події (`docs/architecture.md`, Частина 3 §5): токени, ключі й
  паролі в картці перетворюються на `••••`;
* картки йдуть до телефона тим самим наскрізно зашифрованим каналом, що й
  задачі — Relay їх не бачить.

`install-node.ps1` перед копіюванням показує, що саме запускатиметься, і
питає згоди. Ставте лише ті вузли, які прочитали або яким довіряєте.

---

## 7. У протоколі

Картки їдуть у знімку стану (`docs/protocol.md`, рівень 2):

```json
{
  "t": "snapshot",
  "seq": 42,
  "sessions": [ … ],
  "nodes": [
    {
      "id": "system-info",
      "name": "Система",
      "status": "ok",
      "updated_at": 1737394821000,
      "lines": [ { "label": "Процесор", "value": "32 %" } ],
      "text": ""
    },
    { "id": "gpu", "name": "GPU", "status": "error", "error": "timeout" }
  ]
}
```

Поля `text` і `error` необов'язкові. Застосунок відкидає вузол без `id`,
читає щонайбільше 16 вузлів і 12 рядків у кожному — ті самі межі, що й на
комп'ютері: сторона, яка приймає дані, не довіряє стороні, яка їх надсилає.

## 8. Приклади

У репозиторії, каталог [`nodes/`](../nodes):

| Вузол | Що показує |
|---|---|
| `system-info` | процесор, вільна пам'ять, час роботи |
| `disk-space` | вільне місце на дисках |
| `claude-click` | мишка для Claude Code: «Натискаю: Файл» у чаті |
| `template` | заготовка з коментарями для власного вузла |

Найкоротший робочий вузол — два файли:

```json
{ "name": "Привіт", "run": "run.ps1" }
```

```powershell
[Console]::OutputEncoding = New-Object System.Text.UTF8Encoding $false
'{"status":"ok","lines":[{"label":"Стан","value":"працює"}]}'
```
