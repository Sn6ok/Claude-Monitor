# Claude Monitor

Дивіться з телефона, що зараз робить Claude Code на вашому ноутбуці.

Не віддалений робочий стіл, не трансляція екрана — лише структуровані події:
які задачі виконуються, що саме Claude робить просто зараз, чи не чекає він
на вашу відповідь, чи не сталося помилки.

**beta 2** — до моніторингу додалися [вузли](docs/nodes.md): розширення, які
ви кладете в папку, як моди до гри.

```text
  АКТИВНИХ ЗАДАЧ: 3    ● працює: 2   ◐ чекає: 1   ✕ помилок: 0
  ─────────────────────────────────────────────────────────────
  [46ded809] ○ ОЧІКУЄ      I-FVG структура та розриви
                           Learning TS Claude Code        5:43:10

  [bd9e74e7] ● ПРАЦЮЄ      Master prompt review
                           Input Recoder
                           ├─ створює src/core/event_queue.cpp
                           └─ 6:33:40

  [bf9f1ff9] ◐ ЧЕКАЄ НА ВАС  Виправити авторизацію
                           auth-service
                           └─ 0:41:06
```

## Як це працює

```text
Claude Code  ─(пише транскрипт)─>  Windows Bridge  ─TLS─>  Relay  ─TLS─>  Android
                                        │
                                   спостерігає,
                                   не втручається
```

Bridge читає файли, які Claude Code веде **у будь-якому разі**, і надсилає
з них короткі структуровані події. Він не запускає Claude, не робить знімків
екрана і не може вплинути на його роботу.

Вміст подій зашифрований наскрізно: сервер маршрутизує їх, але не бачить, що
всередині.

## Швидкий старт

Налаштування робиться **один раз** і стосується лише вас: ваш тунель, ваш
токен, ваша адреса Relay. Нічиїх чужих адрес у проєкті немає.

```powershell
.\scripts\setup.ps1
```

Скрипт запитає те, чого не може знати сам: чи користуєтесь ви ngrok, власним
доменом чи лише домашнім Wi-Fi, і токен ngrok, якщо він потрібен. Відповіді
зберігаються **поза репозиторієм**, у `%USERPROFILE%\.claude-monitor`:

| Файл | Що в ньому | Захист |
|---|---|---|
| `setup.json` | спосіб доступу, домен, адреса Relay | доступ лише вашому обліковому запису Windows |
| `ngrok-token.bin` | токен ngrok | зашифрований DPAPI: читається лише цим обліковим записом і лише на цій машині |
| `identity.bin` | приватні ключі Bridge | зашифрований DPAPI |
| `peer.json` | публічні ключі підключених телефонів | лише публічні дані |

Токен вводиться прихованим полем, не потрапляє ні в командний рядок, ні
в журнали, ні в змінні середовища, які видно іншим процесам.

Далі щоразу достатньо однієї команди:

```powershell
.\scripts\start-all.ps1
```

Вона підніме Relay, тунель і Bridge, перевірить увесь ланцюг і надрукує
адресу для застосунку. Якщо налаштування ще немає — так і скаже.
Змінити налаштування: `.\scripts\setup.ps1 -Force`.

### Запуск разом із Windows

За замовчуванням разом із системою не стартує **нічого**: Bridge піднімає хук
`SessionStart`, коли ви починаєте сесію Claude Code. Якщо хочете, щоб Relay
і тунель були напоготові одразу після входу:

```powershell
.\scripts\autostart.ps1 -Enable     # увімкнути
.\scripts\autostart.ps1 -Status     # перевірити
.\scripts\autostart.ps1 -Disable    # вимкнути
```

Використовується Планувальник завдань вашого облікового запису — без прав
адміністратора і без вікон на екрані. Сам Bridge однаково працює лише тоді,
коли є сесії Claude Code: без Claude Desktop і без задач він завершується
через кілька хвилин.

## Встановлення вручну

Те саме, що робить `setup.ps1`, крок за кроком.

### 1. Bridge на ноутбуці

Скопіюйте `claude-monitor-bridge.exe` у зручне місце, наприклад
`C:\Users\<ви>\ClaudeMonitor\`.

Перевірте, що він бачить Claude:

```powershell
.\claude-monitor-bridge.exe --status
```

Ви маєте побачити перелік активних задач Claude Code.

### 2. Relay

Relay — це маленький сервер, через який телефон знаходить ноутбук.
Обидві сторони підключаються до нього самі, тож **жодних портів
відкривати не треба**.

```powershell
cd relay
npm install
node src/index.js
```

Щоб Relay став доступним з інтернету, найпростіше використати
Cloudflare Tunnel — безкоштовно, з валідним сертифікатом і без білого IP:

```powershell
winget install Cloudflare.cloudflared
cloudflared tunnel --url http://localhost:8787
```

Cloudflared надрукує адресу виду `https://щось-випадкове.trycloudflare.com`.
Для застосунку вона знадобиться у вигляді `wss://щось-випадкове.trycloudflare.com/ws`.

> Безкоштовний тунель отримує нову адресу за кожного запуску. Щоб адреса була
> сталою, зареєструйте іменований тунель у Cloudflare — це також безкоштовно.
> Докладніше в [docs/relay.md](docs/relay.md).

### 3. Прив'яжіть Bridge до Claude Desktop

Bridge має запускатися разом із Claude Code — і **не запускатися разом
із Windows**. Для цього використовується офіційний механізм хуків.

```powershell
.\claude-monitor-bridge.exe --set-relay wss://ваша-адреса/ws
.\claude-monitor-bridge.exe --install-hooks
```

Друга команда надрукує фрагмент, який треба додати в
`%USERPROFILE%\.claude\settings.json`. Після цього Bridge стартуватиме
сам, щойно ви почнете сесію в Claude Code.

### 4. Телефон

Встановіть `claude-monitor.apk`.

До одного ноутбука можна підключити **до п'яти телефонів** — кожен зі своїм
ключем шифрування. Процедуру нижче повторюють для кожного телефона; перелік
підключених показує `--status`, а від'єднати зайвий можна командою
`--unpair <перші символи ідентифікатора>`.

На ноутбуці виконайте:

```powershell
.\claude-monitor-bridge.exe --pair
```

З'явиться код виду `KXQ7-M4NP-2WRF`. Введіть у застосунку адресу Relay
та цей код. Код діє три хвилини й одноразовий — далі телефон користується
власним криптографічним ключем.

## Що показує застосунок

**Список задач** — кожна сесія Claude Code окремою карткою: стан, назва,
поточна дія, час роботи, коли востаннє щось змінювалося.

**Деталі задачі** — стрічка подій саме цієї задачі.

**Спільна стрічка** — усі події всіх задач в одному потоці, кожна позначена
своєю задачею.

**Налаштування** — стан з'єднання, споживання Bridge, керування доступом.

### Стани

| Стан | Що означає |
|---|---|
| `ПРАЦЮЄ` | виконує інструмент або формує відповідь |
| `ЧЕКАЄ НА ВАС` | потрібна ваша відповідь чи дозвіл |
| `ОЧІКУЄ` | відповів і чекає наступного запиту |
| `ПОМИЛКА` | остання операція завершилася невдало |
| `НЕВІДОМО` | даних немає — і застосунок про це чесно каже |

## Вузли — розширення

Вузол показує в застосунку те, чого Claude Monitor сам не знає: навантаження
ноутбука, місце на дисках, стан вашої збірки — що завгодно, що вміє
надрукувати рядок JSON.

Влаштовано як моди до гри: поклали каталог у папку — вузол працює, прибрали —
зник. Нічого перезбирати не треба, Bridge перечитує папку сам.

```text
  ВУЗЛИ
  ┌──────────────────────────────────────────────┐
  │ ● Система                                    │
  │   Процесор                              32 % │
  │   Вільна пам'ять               6.1 / 7.9 ГБ  │
  │   Працює                        6 год 10 хв  │
  └──────────────────────────────────────────────┘
  ┌──────────────────────────────────────────────┐
  │ ● Диски                                      │
  │   C:                  62.1 / 226.7 ГБ (27 %) │
  │   D:                 102.5 / 230.6 ГБ (44 %) │
  └──────────────────────────────────────────────┘
```

Встановити готовий приклад із репозиторію:

```powershell
.\scripts\install-node.ps1 .\nodes\system-info
.\scripts\install-node.ps1 -List
```

Власний вузол — це два файли в каталозі:

```json
{ "name": "Привіт", "run": "run.ps1" }
```

```powershell
'{"status":"ok","lines":[{"label":"Стан","value":"працює"}]}'
```

Мова будь-яка: `.ps1` запускається через PowerShell, `.js` — через Node,
`.py` — через Python, `.exe` — напряму.

Вузол може не лише показувати картку, а й **підписувати команди** Claude Code
рядком у чаті. Саме так працює готовий мод `claude-click` — мишка для
Claude Code:

```text
  [10:24:31] ⚙ Claude Click
             Натискаю: Файл
```

```powershell
.\scripts\install-node.ps1 .\nodes\claude-click
```

> **Вузол — це чужий код, який виконується з вашими правами.** Тому він
> запускається лише з вашої папки, обмежений часом і розміром виводу, не
> отримує ні ключів, ні вмісту ваших сесій, а його вивід проходить те саме
> маскування секретів, що й звичайні події. Ставте лише ті вузли, яким
> довіряєте.

Формат, межі, коди помилок і приклади — [docs/nodes.md](docs/nodes.md).

## Безпека

| | |
|---|---|
| Транспорт | TLS, перевірка сертифіката ніде не вимикається |
| Вміст подій | AES-256-GCM наскрізно: Relay не бачить, що всередині |
| Ключі на ноутбуці | DPAPI, прив'язка до облікового запису Windows |
| Ключі на телефоні | Android Keystore, за наявності — апаратний модуль |
| Автентифікація | ECDSA P-256, challenge-response, без сталих паролів |
| Підключення | код на 60 бітів, 3 хвилини, одноразовий, 5 спроб |

Застосунок працює **лише на перегляд**: він не може виконати команду,
змінити файл чи натиснути щось на ноутбуці.

Якщо телефон загублено:

```powershell
node relay/src/index.js devices          # знайти пристрій
node relay/src/index.js revoke <id>      # відкликати доступ
```

Відкликання діє негайно, а не з наступного підключення.

Докладна модель загроз — у [docs/security.md](docs/security.md).

Фактичні виміри, не оцінки:

Bridge більшість часу спить на об'єктах ядра: він прокидається лише коли

## Чого система не робить

Це свідомі межі, а не незавершена робота:

- не транслює екран і не робить знімків
- не перехоплює клавіатуру й мишу
- не дозволяє керувати ноутбуком із телефона
- не запускає другого Claude Code
- не читає пам'ять чужих процесів і не змінює Claude Desktop
- не стартує разом із Windows

## Обмеження, про які варто знати

**Назва задачі** береться з `custom-title`, якщо він є. Інакше — з тексту
першого запиту або з назви каталогу. Застосунок завжди показує, звідки взято
назву, щоб ви не сприймали здогадку за факт.

**Стан `НЕВІДОМО`** з'являється, якщо формат транскрипту зміниться після
оновлення Claude Code. Це навмисно: краще чесне «не знаю», ніж вигадана
впевненість.

**Застосунок не тримає з'єднання у фоні.** Він підключається, коли ви його
відкриваєте. Постійний фоновий сокет з'їдав би батарею заради екрана,
на який ніхто не дивиться.

**Один Bridge на комп'ютер.** Він стежить за всіма сесіями Claude Code
одночасно, тож другий екземпляр не потрібен і не запуститься.

## Структура репозиторію

| Каталог | Що всередині |
|---|---|
| `bridge/` | Windows Bridge: C++20 без зовнішніх залежностей — читає транскрипти, шифрує, надсилає |
| `relay/` | Relay на Node.js: автентифікація, авторизація, маршрутизація; вмісту не бачить |
| `android/` | застосунок: Kotlin + Jetpack Compose, єдина залежність — OkHttp |
| `nodes/` | готові вузли-приклади та заготовка для власного |
| `scripts/` | `setup.ps1` (одноразове налаштування), `start-all.ps1`, `autostart.ps1`, `install.ps1`, `install-node.ps1` |
| `docs/` | архітектура, протокол, безпека, Bridge, Relay, вузли, усунення несправностей |

Нічого особистого в репозиторії немає й бути не може: ключі, токени та перелік
телефонів живуть у `%USERPROFILE%\.claude-monitor` і закриті `.gitignore`.
